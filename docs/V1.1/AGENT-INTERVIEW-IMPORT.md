# Agent 面试题批量导入

本次导入来自 `interview.md`，共 **24 道主问题、79 道追问**。原文按 Markdown 结构解析，不调用 AI，不改写回答。

## 导入规则

- 模块：执行时查找名称为 `Agent` 的启用模块，忽略大小写和名称两端空格。不存在或存在多个匹配模块时，报错并回滚，不新建模块。
- 难度：简单（`EASY`）。
- 掌握状态：未开始（`NOT_STARTED`）。
- 标签：关联导入时已有的全部标签，不新建标签；没有标签也可以导入。
- 每个二级标题作为一道主问题；标题下、首个追问前的正文作为答案；详细解释留空。
- 每个 `提问：` 和其后正文保存为结构化追问，沿用当前页面的 `version: 1` JSON 格式；回答开头的 `回答：` 标记不存入正文。没有该标记的回答也会保留。
- 保留答案中的 Markdown 段落、列表、加粗、表格和代码块，追问不作为独立主问题入库。

## 执行

先备份目标数据库。数据库需要已完成此前的面试题字段精简迁移，并具备 `answer`、`follow_up_questions` 字段；缺少追问字段时，先执行同目录下的 `QUESTION-FOLLOW-UPS-MIGRATION.sql`。旧数据库还需先执行 `QUESTION-ID-IDENTITY-MIGRATION.sql`，将面试题主键转换为自增整数。

在数据库客户端中，使用同一连接**完整执行**同目录下的 `AGENT-INTERVIEW-IMPORT.sql`，不要只选中其中部分语句执行。脚本使用事务，不修改表结构，也不写资料库或索引任务。

脚本自动定位模块和标签，不需要手填 ID。面试题 ID 由数据库自增生成，新增题目按文档顺序依次导入；已有同名题目会跳过，不重排其 ID。正常首次执行且没有同名题目时，执行消息会显示新增 24 道主问题、跳过 0 道；79 道追问包含在主问题的 `follow_up_questions` 中，不单独新增 79 行。

导入后进入 AI 面经页面刷新即可查看，必要时将筛选条件恢复为全部。

## 重复执行

同一模块下存在相同问题标题时（忽略标题两端空格），跳过该题，不覆盖其答案、追问、难度、掌握状态或标签。重复执行不会给已跳过题目补充后来新建的标签。

脚本执行期间会短暂阻塞面试题表的其他写入，以保证并发导入不会产生重复题目。任何步骤失败都会回滚本次事务；数据库客户端若仍显示事务未结束，先执行 `ROLLBACK;`，排查后再重新完整执行脚本。
