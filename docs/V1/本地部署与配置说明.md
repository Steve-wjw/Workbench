# AI 工作台 V1 本地部署与配置说明

## 1. 环境要求

Java 21、Maven 3.9+、Python 3.14、Node.js 22+、npm、PostgreSQL 16 及 pgvector。Python 工程限定 3.14，不使用其他版本虚拟环境代替。

以下命令在项目根目录运行。工程发布标识统一 1.0.0，接口路径仍为 `/api/v1` 和 `/internal/v1`。本次文档定版不自动升级数据库或重启已有服务。

## 2. 配置

根目录已有 `.env` 时保留，不要覆盖。首次配置可执行：

```bash
test -f .env || cp .env.example .env
```

配置值只在本机填写，不提交 Git。`start-local.sh` 使用 Bash 加载并导出根目录 `.env`；通过 IDE/其他终端手动启动 Java 时，需要另行传入对应环境变量，并非 Java 自动读取根目录 `.env`。

| 配置项 | 用途与注意事项 |
| --- | --- |
| DATABASE_URL | Python、数据库脚本的 PostgreSQL 连接地址；特殊字符需 URL 编码 |
| SPRING_DATASOURCE_URL/USERNAME/PASSWORD | Java JDBC 地址及凭证；必须与 Python 指向同一个目标库 |
| POSTGRES_DB/USER/PASSWORD/PORT | 本地数据库辅助配置；不能代替 Java 所需全部配置 |
| WORKBENCH_DATA_DIR | 建议填写绝对路径；相对路径受 Java 工作目录影响 |
| VITE_API_BASE_URL | 默认 `http://localhost:8080/api/v1`；仅可放公开 API 地址，不能放 Token |
| SERVER_PORT | Java 实际监听端口，代码默认 8080 |
| JAVA_API_PORT | 启动脚本显示地址使用；当前不自动映射 SERVER_PORT，改端口需两者同步 |
| PYTHON_RAG_PORT/PYTHON_RAG_BASE_URL | Python 监听端口、Java 调用 Python 的地址 |
| FRONTEND_PORT | 启动脚本中的 Vite 端口，默认 5173 |
| DEEPSEEK_API_KEY | 仅“资料生成面经”需要 |
| DEEPSEEK_BASE_URL | 默认 `https://api.deepseek.com`；需兼容 `/chat/completions` |
| DEEPSEEK_CHAT_MODEL | 默认 deepseek-chat |
| GITHUB_TOKEN | 可选，后端访问公开仓库 API 时使用；不启用私有仓库产品能力 |
| EMBEDDING_DIMENSION | 默认 1024，需与 pgvector 列维度一致，不应随意更改 |
| EMBEDDING_MODEL | 保留的配置名称，当前不下载或运行该名称的模型 |
| RAG_CHUNK_MAX_TOKENS | 当前分片长度参数，默认 420 |

手工维护资料、题目和标签无需聊天模型密钥。AI 热点只要求新闻源可访问，不需要模型 Key。GitHub 浏览已存数据不依赖每次访问 GitHub。

前端直接使用 `frontend/.env.local` 或启动时 Vite 环境变量；根目录 `.env` 只有经过统一脚本导出后才传到该进程。修改配置后通常需重启对应进程。

## 3. 安装与构建

```bash
python3.14 -m venv backend-python/.venv
backend-python/.venv/bin/python -m pip install -e './backend-python[dev]'
npm --prefix frontend ci
npm --prefix frontend run build
mvn -f backend-java/pom.xml test
```

依赖安装需要可用网络或本机缓存。离线 Maven 验证可用 `mvn -o -f backend-java/pom.xml test`，前提是依赖已经缓存。

## 4. 新建数据库与旧库升级

### 全新数据库

先安装 pgvector、创建目标数据库并配置连接，然后执行：

```bash
bash scripts/init-local-database.sh
```

脚本使用 `infra/postgres/init/001-create-schemas.sql` 和 `002-create-business-tables.sql`，当前新库结构包含追问、题目来源、自增题目 ID 和 GitHub 项目表。新库不要先跑历史字段精简 SQL 再建表。

### 已有数据库

先停止业务写入并备份，按 [数据库脚本使用说明](SQL/数据库脚本使用说明.md) 检查实际缺失项，选择性执行迁移。不能认为重复运行初始化脚本就会自动完成所有历史结构转换。

不使用清库脚本完成升级。本次文档整理未连接或变更业务数据库。

## 5. 启动、检查与停止

```bash
bash scripts/start-local.sh
```

统一启动 Java API、Python API、Python worker 和 Vite。已经由 PID 文件登记且存活的进程不会被自动重启；修改后端代码或环境变量后需停止并重新启动，不能只刷新网页。

默认入口：

- 前端：`http://localhost:5173`
- Java 存活：`http://localhost:8080/api/v1/health/live`
- Java 综合健康：`http://localhost:8080/api/v1/health`
- Python 健康：`http://localhost:8000/internal/v1/health`
- Swagger UI：`http://localhost:8080/swagger-ui.html`

侧栏只看 Java 存活，不检查依赖。综合健康检查数据库及 Python API，但仍不证明 worker 正常，需用测试资料的索引完成情况确认。

```bash
bash scripts/stop-local.sh
```

只停止脚本管理的服务，不停止 PostgreSQL。IDE/手动终端启动的进程需在原位置停止。脚本使用 Bash，不用 `sh` 执行。

## 6. 日志与数据

| 位置 | 内容 |
| --- | --- |
| `data/logs/java-api.log` | Java 业务及请求日志 |
| `data/logs/python-rag.log` | Python API |
| `data/logs/python-worker.log` | 索引任务处理 |
| `data/logs/frontend.log` | Vite 运行信息 |
| `data/.pids/` | 统一脚本管理的进程标识 |
| 实际 `WORKBENCH_DATA_DIR/imports/` | 上传 Markdown 副本 |

日志/PID 目录由启动脚本固定在项目 `data/` 下，不随 WORKBENCH_DATA_DIR 改变。数据库之外的上传副本要同时纳入备份。

## 7. 外网与代理

Java 会访问模型服务、AIHOT、GitHub，以及配置中的本地 Python API。代码没有为每项功能强制设置一个统一代理；JVM 启动属性或系统默认选择器可能决定其网络路径。

之前排查时发现某次运行的 Java 设置了 HTTP/HTTPS 代理 `127.0.0.1:7890`：AIHOT 直连成功、经代理 TLS 超时。该结论是当时环境的诊断记录，不代表永远必须取消代理。

取消后端代理会使相关请求改走直连；本地业务通常不依赖外网代理，但 GitHub 或某些模型服务的可达性取决于网络。更改前应检查配置来源（IDE VM options、JVM 环境变量或启动参数），必要时只对目标站点配置直连。不要关闭整机代理来替代对后端的判断，也不要把 Token 或整个进程环境打印出来排查。

新闻故障与 GitHub 配额分别排查，代理可用并不意味着上游无限额。外部失败不影响已入库资料和题目的正文保存。

## 8. 运行边界

没有登录与权限隔离，不建议直接暴露公网。Python 和前端统一脚本绑定回环地址，Java 仍需按实际监听及防火墙设置限制访问，不能仅依赖产品名中的“本地”。

全量清理脚本 `scripts/clear-local-database-data.sh` 会清空业务数据，必须用户明确确认、先备份并停服务，日常安装、升级、测试不执行。

验证入口：[测试与验收说明](测试/测试与验收说明.md)。
