# 数据库脚本使用说明

本目录保存 V1 可能用到的手动迁移、检查和导入 SQL，已将旧 V1/V1.1 文件统一改为中文名称。**不自动执行，也不要按目录批量执行全部脚本。** 本次仅整理文件和引用，未操作业务库。

## 2. 新库与旧库分开处理

全新空库使用项目根目录命令 `bash scripts/init-local-database.sh`，入口仍是：

- `infra/postgres/init/001-create-schemas.sql`
- `infra/postgres/init/002-create-business-tables.sql`

这些是工程初始化文件，保留原名和原目录以维护脚本职责，不是本目录的历史手工迁移。新库当前已经包含所需字段、GitHub 表和自增题目 ID，不必再执行历史转换。

已有数据库先查看实际结构，不要只凭文件名判断“都没有用”或“都要再跑一遍”。初始化中的 IF NOT EXISTS 不会将已有 UUID 列转换成 BIGINT，也不会完成任意旧字段升级。

## 3. 旧库执行顺序

1. 停止 Java、worker 等写入，先做整库及上传文件备份，确认目标连接。
2. 仅在还没精简字段时执行“面试题与分类字段精简迁移”。它会删除 source_type；**已是当前结构的库不要重跑**。
3. 缺少追问字段时执行“面试题追问字段迁移”。
4. 题目还是 UUID 时，先运行只读“检查面试题外键引用”，确认依赖后完整执行“面试题自增主键迁移”。
5. 在字段精简完成后执行“面试题创建来源迁移”，确保最后保留来源字段；旧题统一为 MANUAL。
6. 缺少 GitHub 表时执行“GitHub项目建表”。
7. 按需执行某一批题目导入，不是每次启动的前置条件。
8. 启动更新后的服务并按验收文档核对内容、关联、ID 和页面。

每个迁移/导入文件使用同一连接完整执行，不只框选中间部分。脚本失败时，若客户端仍处于失败事务，先在原连接执行 `ROLLBACK;`，解决原因后再执行；不要绕过未知依赖保护或使用 DROP CASCADE 强行推进。

## 4. 自增主键及外键说明

只转换 `core.interview_questions.id` 及以下已知引用：

| 引用列 | 说明 |
| --- | --- |
| `core.interview_question_tags.question_id` | 标签关系 |
| `core.ai_question_drafts.accepted_question_id` | 旧库可选，保留历史记录 |
| `core.interview_question_sources.question_id` | 旧库可选，保留历史来源 |

可选表不存在就跳过，不新建历史表。存在时保留引用列、索引、唯一性及原有外键属性，非空引用缺少映射则报错。不额外保留 UUID 列，不把模块/标签/资料主键一并转换。

旧题按 created_at、旧 ID 排序赋号，无法由相同时间戳还原原文顺序；新导入题目按文档顺序生成 ID。编号可有空缺，删除不重排，成功迁移后重复执行不重新编号。旧 UUID 链接失效。

如果报 `Additional tables reference interview_questions`，说明存在未纳入计划的外键；先回滚，再运行只读检查，把 `requires_migration_plan` 行用于补充迁移。不要直接删除历史表或外键。

## 5. 三批题目的区别

| 规则 | 第一批 | 第二批 | 第三批 |
| --- | --- | --- | --- |
| 来源文档 | interview.md | interview2.md | interview3.md |
| 主问题 / 追问 | 24 / 79 | 15 / 46 | 10 / 28 |
| 模块 | 现有启用的 Agent | 现有启用的 Agent | 现有启用的 Agent |
| 难度 / 掌握 | EASY / NOT_STARTED | EASY / NOT_STARTED | 标题中的难度 / NOT_STARTED |
| 标签 | 导入时已有的全部标签，不新建 | 各二级标题末尾括号中的标签，缺少则新建 | 标题末尾“难度-标签”中的标签，缺少则新建 |
| 来源字段 | 使用数据库默认 MANUAL，应先完成来源迁移 | 显式 MANUAL | 显式 MANUAL |

三批都按二级标题拆主问题、首个追问之前的正文作答案，保留 Markdown，追问以现有 version:1 结构化文本存到主问题，不另写独立题目行。不调用 AI，不改写或核验技术观点，不写资料库或索引任务。

均要求恰好一个名称匹配 Agent 且 ACTIVE 的模块，忽略大小写和两端空格；不存在或有多个则回滚。相同模块下同标题（忽略两端空格）跳过，不覆盖已有内容、状态或标签，不对语义相近题目自动合并。

### 第二批标签

8 个标签名为：大模型、AI、MCP、协议原理、安全性、开发实践、Manus、Agent。无同名题目时共关联 42 条，重复标签名通过已有记录复用，不按“所有已有标签”关联。

按忽略大小写与两端空格匹配已有标签，缺失创建顶级标签；多个已有标签匹配则回滚，需先整理重名项。“LLM Agent 常见功能有哪些？”未标标签，保持无标签。

第二、三批等待锁最多 10 秒。三批导入都会短暂阻塞相关业务写入，安排空闲期执行；重复执行跳过已存在题目，不为跳过题补新增标签。

### 第三批难度与标签

按标题中的“简单 / 中等 / 困难”分别写入 EASY / MEDIUM / HARD，共 3 / 5 / 2 道。标题不包含末尾难度和标签括号；掌握状态均为 NOT_STARTED，来源均为 MANUAL，详细解释留空。

12 个标签名为：大模型、AI Agent、LangChain、AutoGPT、AI、A2A、系统架构、技术栈、MCP、后端、编程导航、场景题。无同名题目时共关联 32 条。“AI Agent”为一个完整标签，不按空格拆分；匹配已有标签和重名保护规则与第二批一致。

OpenManus 那题原文没有追问，follow_up_questions 为 NULL；其余 9 道主问题合计 28 道追问。“详细解答可以看”等追问补充说明一并保留到追问答案。新题按照原文顺序获取自增 ID，不改动已有题目的编号或内容。

建议备份后，在同一连接完整执行 [导入Agent面试题第三批.sql](导入Agent面试题第三批.sql)。执行结束通过 NOTICE 查看实际新增、跳过、创建标签和关联数量。只生成脚本不会自动向业务库导入。

## 6. 验证与保留

迁移测试仍位于 `scripts/tests/`，读取的是本目录新文件名，测试步骤见 [测试与验收说明](../测试/测试与验收说明.md)。第二批曾在独立临时 PostgreSQL 验证数量、默认值、标签复用、重复执行、同名保护及失败回滚；不代表用户业务库已经导入。

第三批于 2026-11-22 通过独立临时 PostgreSQL 的 8 项测试，涵盖 10/28/32 数量、难度与 Markdown 保留、标签复用、重复执行、同名题保护、模块校验和失败回滚。命令为 `node --test scripts/tests/interview-third-import.test.mjs`，仅连接测试自行创建的临时集群，未向业务库导入。

这些文件是升级依据、数据重导入来源和测试输入，保留在版本库有实际用途。文件移动不改变数据库，不应因此再次执行已完成的迁移。
