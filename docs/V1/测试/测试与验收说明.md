# AI 工作台 V1 测试与验收说明

## 1. 范围与原则

版本 V1 / 1.0.0。本说明覆盖原 V1 与 V1.1 合并后的功能。测试代码留在各工程中，本目录只集中维护测试文档。

步骤不是通过结论；本次实际结果见 [V1定版验证记录](V1定版验证记录.md)。自动化模拟通过不代表真实模型、外部新闻、GitHub、代理或业务数据库都已验证。

优先使用独立测试库。人工页面验证使用 `V1验收-` 前缀，不修改学习资料；不运行全量清库脚本，不读取或输出密钥，不对未知公网服务做压力请求。

## 2. 环境与自动化命令

先按 [部署说明](../本地部署与配置说明.md) 安装依赖和配置测试环境。

```bash
mvn -o -f backend-java/pom.xml test
npm --prefix frontend test
npm --prefix frontend run build
backend-python/.venv/bin/python -m pytest backend-python/tests
node --test scripts/tests/question-identity-migration.test.mjs
node --test scripts/tests/github-projects-migration.test.mjs
node --test scripts/tests/interview-third-import.test.mjs
git diff --check
```

Maven 离线需预缓存依赖，缺失时经许可联网安装。SQL 测试要求 initdb、pg_ctl、psql 和本机共享内存/Unix socket 权限，各自创建临时集群、测试后关闭，不连接业务库；环境不允许时记录阻塞，不换到真实业务库测试。

| 层次 | 覆盖重点 |
| --- | --- |
| Java | 资料状态、Repository SQL、BIGINT 序列化、来源保留、分页、新闻和 GitHub 模拟请求；不代表生成解析和所有 Service 分支已覆盖 |
| 前端 | Markdown 安全与格式、追问结构、来源参数、导航恢复、连接状态、GitHub 组件和请求 |
| Python | Markdown 解析、分片、哈希向量、索引流程及内部 API |
| 主键迁移 | 旧引用转换、历史表、索引约束、失败回滚、重跑、导入顺序 |
| GitHub 建表 | 重跑、分类唯一性、字段约束、与初始化结构一致 |
| 第三批面试题导入 | 10 道主问题、28 道追问、难度和 Markdown 保留、标签复用、重复执行及失败回滚 |

主键与 GitHub 测试脚本已经改为读取 `docs/SQL/` 下的中文文件。需要核对第二批题目导入时，在独立库手工运行对应 SQL，检查 15/46/42 数量和重复执行保护。

## 3. 启动与健康

```bash
bash scripts/start-local.sh
curl -sS -i http://localhost:8080/api/v1/health/live
curl -sS -i http://localhost:8080/api/v1/health
curl -sS -i http://localhost:8000/internal/v1/health
```

存活接口只查 Java；综合检查需 database/pythonRag 均 UP。worker 是否正常必须通过测试资料完成索引确认。不要用 curl -f 丢弃错误正文后继续当正常 JSON 处理。

## 4. 页面验收矩阵

| 模块 | 操作 | 预期 |
| --- | --- | --- |
| 导航 | 打开 7 个入口 | 首页、热点、面经、资料库、GitHub、标签、模块均可进入 |
| 刷新恢复 | 在题目/资料/GitHub/新闻详情刷新 | 恢复对应页面和有效详情；失效内容回列表 |
| 连接状态 | 正常及 Java 不可达时检查侧栏 | 显示真实 Java 可达性，不将新闻失败等同后端断线 |
| 首页 | 查看指标和列表 | 数量正确、题目 ID 顺序前 5 条、资料按最近更新，不显示答案 |
| 模块 | 新建并删除专用模块 | 内容引用可用，删除后内容保留且未分类 |
| 标签 | 新建、改颜色、删除 | 修改有效，删除只移除关联 |
| 快捷分类 | 内容表单直接新建模块/标签 | 能选择新分类；取消主表单不会伪称撤销分类 |
| 标签推荐 | 输入已有标签名相关正文 | 目标最多 3 个、不调用模型；当前分页问题列为待修复，不能直接判通过 |
| 手工资料 | 保存含列表、表格、代码块的 Markdown | 原文不丢失，创建后台任务 |
| Markdown 导入 | 粘贴和文件各导入一次 | 正常入库；上传有副本；同正文未归档导入复用 |
| 资料详情 | 切换预览/原文/规范化，查看任务 | Markdown 安全，处理完成状态正确 |
| 资料重建 | 改正文、重新索引、重复点击 | 新结果对应新正文，活跃任务不积压重复 |
| 资料归档 | 归档再恢复 | 归档不被任务覆盖，恢复后可重新处理 |
| 资料删除 | 先取消后确认 | 取消无变化；确认清理任务/片段，已保存题目保留 |
| 生成面经 | 无 Key、有模拟或测试模型分别验证 | 无配置明确失败；结果最多 3 条，未确认不入库 |
| 生成保存 | 确认后查题目、模拟中途失败 | 继承分类，来源 DOCUMENT；记录部分保存风险 |
| 面试题 | 填问题、答案、可选解释、状态和分类 | 内容与选择一致，默认手工 MANUAL |
| 面试题列表 | 筛选、编辑后比较排序 | ID 升序稳定，不展开答案，追问标题在下一级 |
| 追问 | “+”新增多条，编辑、删除、预览/原文 | 两个字段均保留 Markdown，详情保存立即生效 |
| 追问兼容 | 打开旧 Markdown 追问 | 正文、子标题、代码保留，修改后结构化保存 |
| 来源保留 | 编辑手工题和资料生成题 | 编辑不改变原来源 |
| 热点 | 成功、空结果、断网/上游错误、无评分 | 今天/昨天各至多 5 条，排序正确，失败不伪装无新闻 |
| 热点缓存 | 连续进出、短间隔刷新、跨日失败 | 缓存/退避有效，旧日内容不冒充今天 |
| 热点重试 | 超时/连接错误、502/503/504 后恢复或持续失败 | 仅重试失败页，每页最多 3 次，耗尽后冷却 15 秒；成功不留错误警告 |
| 热点限流 | 429、带 Retry-After 的 503；秒数及 HTTP 日期 | 不立即重试，遵守上游等待；权限/证书/格式错误不重试 |
| 热点总耗时 | 后续分页卡住、响应正文缓慢、重试等待、并发进入 | 共享 15 秒预算并取消超时任务，并发不重复获取；同日缓存继续可用 |
| GitHub 分类 | 两类分别添加同一公开仓库 | 跨类可存，同类重复 409，不修改远程账号 |
| GitHub 地址 | 非 HTTPS、非 GitHub、内部路径、带凭证 | 参数拒绝，不向任意地址发请求 |
| GitHub 备注 | Markdown 预览/原文、编辑、换分类 | 个人内容持久化，同步不覆盖 |
| GitHub 同步 | 首次失败、成功、304、限流、仓库改名 | 待同步可保存，失败保留旧数据，安全跳转，冲突不覆盖 |
| GitHub 搜索 | 查询名称/简介/备注并翻页 | 按分类过滤，总数与分页正确 |
| 安全显示 | Markdown 中加入脚本及危险链接 | 不执行原始 HTML/脚本，不开放危险链接 |
| 持久化 | 停服务再启动 | 业务内容保留，新闻进程缓存可消失 |
| 窄屏 | 缩窄窗口浏览长题目、表格、弹窗 | 无主要控件遮挡，导航/内容/弹窗可滚动 |

当前题目/资料页面前 100 条限制应作为已知边界验证，不把后端分页支持误记成前端已完整翻页。

## 5. 只读数据库核对

以下查询在明确的测试目标库运行，不自动执行迁移：

```sql
SELECT id, question, difficulty, mastery_status, source_type,
       jsonb_array_length(NULLIF(follow_up_questions, '')::jsonb->'items') AS follow_up_count
FROM core.interview_questions
WHERE question LIKE 'V1验收-%'
ORDER BY id;

SELECT id, title, status, index_error, indexed_at
FROM core.documents
WHERE title LIKE 'V1验收-%'
ORDER BY updated_at DESC;

SELECT d.title, j.status, j.attempt_count, j.error_message
FROM core.index_jobs j
JOIN core.documents d ON d.id = j.resource_id
WHERE d.title LIKE 'V1验收-%'
ORDER BY j.created_at DESC;

SELECT resource_id, COUNT(*)
FROM core.index_jobs
WHERE status IN ('PENDING', 'RUNNING', 'RETRY_WAITING')
GROUP BY resource_id HAVING COUNT(*) > 1;

SELECT category, full_name, sync_status, last_synced_at
FROM core.github_projects
ORDER BY category, id DESC;
```

第一条追问数量查询仅适用于确认是 version:1 JSON 的专用测试题，不能直接对旧 Markdown 字段全表强制转 JSON。验收时同时核对标签关联及片段，不通过删除真实记录证明功能。

模型输出解析、标签推荐 Service 的分页边界、完整前后端连库流程仍需补充针对性测试；现有 MockMvc/记录型 Repository 测试不能代替这些验收。

## 6. 故障与收尾

记录测试时间、命令、状态、错误请求 ID。400 检查参数，409 检查重复/冲突，502 检查模型或上游，500 查 Java 日志；任务异常查 worker。不要把网络超时当作“源站一定停服”，也不要把限额故障归因数据库。

只清理带测试前缀的内容及专用分类，上传副本经核对后单独清理。真实仓库的备注测试应使用独立测试记录，删除仅限已确认的本地测试项。禁止用全量清库作为验收收尾。
