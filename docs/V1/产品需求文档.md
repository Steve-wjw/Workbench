# AI 工作台 V1 产品需求文档

## 1. 版本与基准

产品版本 V1，工程版本 1.0.0，定版日期 2026-11-19。合并原 V1 与 V1.1 的已实现功能，以当前工作区代码为事实基准。本文描述已有产品，不延续旧 V2 路线图；已知缺口不等同于本次新增开发承诺。

## 2. 定位与目标

面向个人本地使用的 AI 学习工作台，将学习资料、面试复习、行业热点和 GitHub 项目集中管理。

核心目标：

- 资料可导入、阅读、维护和分类，原文不依赖外部模型。
- 面试题可整理答案、追加追问、记录难度与掌握状态，顺序稳定。
- 一份资料可辅助生成面经，但必须由用户确认后保存。
- 快速阅读今天和昨天的 AI 新闻概述，不维护新闻库。
- 将自研项目与学习收藏的开源项目区分保存，随时打开仓库。

主要用户是工作台所有者本人。当前不提供账号、多人空间、权限隔离或面向公网的发布能力。

## 3. 范围总览

| 功能域 | V1 范围 | 依赖 |
| --- | --- | --- |
| 首页 | 资料数、面试题数、按 ID 顺序的前 5 道题、最近更新的前 5 份资料 | Java、数据库 |
| AI 面经 | 新建、详情、编辑、删除、筛选、追问、来源标识 | Java、数据库 |
| 资料库 | 手工录入、粘贴/上传 Markdown、详情、编辑、索引、归档、删除 | Java、数据库；索引需 Python worker |
| 资料生成面经 | 根据资料生成最多 3 条待确认结果，确认后保存 | 模型 API |
| AI 热点 | 北京时间今天和昨天各最多 5 条、概述详情、原文链接 | AIHOT 公共接口 |
| GitHub | 自研/开源分类、地址录入、概况、备注、搜索、分页、同步 | 本地库；获取概况需 GitHub API |
| 模块与标签 | 创建、查询、删除；标签编辑及颜色；录入时快捷创建分类 | Java、数据库 |
| 运行辅助 | 页面位置恢复、连接状态、错误反馈、任务历史 | 浏览器、各本地服务 |

## 4. 业务对象与分类

模块是资料和题目的一级主题分类；每份资料、每道题至多关联一个模块，可未分类。标签用于跨主题标记，支持多选。模块与标签均不再使用 `slug`。

删除模块后关联资料和题目保留、模块置空；删除标签后仅移除关联，不删除内容。GitHub 使用独立的“自研/开源”分类，不复用模块与标签。

模块管理页面当前提供新建、列表和删除；后端虽有更新接口，不能据此认定页面具备模块编辑能力。标签父子关系是数据/API 能力，当前页面不提供完整树形管理。

## 5. AI 面经

### 内容与阅读

主问题包括：问题、答案、详细解释（非必填）、模块、难度、掌握状态、标签；可附多条追问，每条由“追问”“回答”组成，两项均支持 Markdown。

列表只展示主问题、分类状态及下一级追问标题，不展示答案。点击后进入详情，提供 Markdown 预览和原文切换，答案、解释、追问均可阅读。追问通过“+”添加，可逐条编辑和删除；详情中的追问保存会立即写库，主问题编辑表单中的追问随表单一起保存。

### 顺序、状态与来源

- 题目由数据库生成 BIGINT 自增主键，按 `id ASC` 排序，不因编辑移动位置；允许删除或事务回滚产生编号空缺。
- 难度为简单、中等、困难；手工新建表单默认中等。批量导入脚本默认简单，二者不要混淆。
- 掌握状态为未开始、学习中、已掌握，默认未开始。
- 来源为手动增加（`MANUAL`）和资料库生成（`DOCUMENT`）；已有题目迁移后默认手动增加，编辑不改变来源。
- 手工保存及文档 SQL 导入不调用 AI；资料库点击生成面经才调用模型。

关键词、模块、标签、难度和掌握状态用于筛选。当前页面在加载到的前 100 条题目上筛选，后端分页接口存在但页面尚未提供完整翻页；不将其描述为无限规模题库。

## 6. 资料库与面经生成

### 资料录入和处理

资料可手工填写标题、正文，也可从统一的“导入 Markdown”入口粘贴或上传 `.md`/`.markdown`。支持选择模块和标签、快捷新建分类。Markdown 导入按正文哈希复用已有未归档资料，不把手工新建描述成全面去重。

保存非归档资料后创建索引任务。worker 完成规范化、切片和本地向量计算；状态为待索引、索引中、已索引、失败或已归档。正文变更或恢复归档可重新处理，活跃任务复用。失败不删除原文。

详情提供预览、原文、规范化文本、任务记录、重新索引、编辑及删除。删除资料清理关联任务和片段，不删除已保存面试题；上传文件副本不自动删除。

页面目前主要提供关键词搜索，在已加载的前 100 条资料内筛选；后端另外支持模块、标签、状态和分页参数，不等同于页面已有这些全部控件。

### 资料生成面经

点击资料详情“生成面经”，根据标题与正文生成最多 3 道题。单次只提交正文前 14,000 个字符，不保证覆盖长文全文。结果含问题、答案、详细解释和难度，未确认不入库。

用户确认保存后沿用资料的模块、标签，掌握状态为未开始、来源为资料库生成。结果不是事实核验，用户应先检查。当前为逐题请求保存，不是一个原子批量事务；中途失败时可能已保存部分题目，再次保存前需检查重复。

### 标签推荐

设计和已有算法：从内容中匹配已有标签名称，按出现次数、使用次数排序，最多推荐 3 个，用户自主选择；不调用模型、不自动造标签。当前实现存在分页参数边界问题，详见技术方案的已知限制，不能把推荐成功当成已经完成的验收结论。

## 7. AI 热点

进入页面读取北京时间当天及前一天的新闻。今天按发布时间取最新最多 5 条，昨天按来源热度评分取最多 5 条，同分按时间；没有评分时按时间补充并提示，不声称全网热榜。

展示标题、原文来源、发布时间、分类、概述；详情展示完整概述、关注理由（若有）和外链。当前内容直接来自 AIHOT，保留归属及原文入口，不自行生成概述。

不建表、不保留持久化接口、不定时采集。服务端仅有 10 分钟进程内缓存，刷新请求至少间隔 1 分钟，并尊重上游退避。同一天更新失败可显示旧快照及警告，无快照时显示错误，不能把网络故障显示成“无新闻”。

当前仅个人本地阅读；公开或商业使用前需另行确认内容授权，不将接口可访问等同于无限制转载许可。

## 8. GitHub 项目

“自研”对应 `PERSONAL_DEMO`，“开源”对应 `LEARNING`，由用户选择，不按作者自动判断，也不等于 GitHub Star。

新增完整公开仓库根地址，可先获取概况或直接保存；支持个人 Markdown 备注。概况含简介、主要语言、Stars、Forks、Topics、归档标记、最近推送和最后成功同步时间。

分类分别存储及统计，可搜索仓库全名、简介、备注并分页，默认按新增 ID 倒序。编辑只修改分类及备注，不能直接编辑上游概况；删除只删本地记录，不操作远程仓库。

同分类同仓库禁止重复，两类可各保存一次。获取失败仍可保存合法地址为待同步，不能据此证明远程仓库存在；已有记录同步失败保留旧概况。仅预览、新增、手动同步请求上游，日常浏览读本地数据库。

## 9. 通用体验与安全

保持现有中性色、青绿色强调、紧凑列表、细边框、图标按钮和 Markdown 阅读方式，不为小功能引入独立设计体系。

浏览器同一标签页刷新恢复当前页面、详情 ID 和 GitHub 分类，不保存正文、未提交表单和全部筛选项。内容删除或详情失效时回对应列表，不承诺跨标签页或关闭浏览器后恢复。

“后端已连接”只表示 Java 存活接口可达，不代表数据库、worker、模型、新闻源或 GitHub 可用。删除需确认；密钥仅服务端配置，不入前端或普通日志；不执行 Markdown 原始 HTML。

## 10. 非范围与验收边界

V1 不含全局 AI 问答、全局语义搜索、多用户、同步 GitHub Star、私有仓库读取、源码下载、新闻持久化、定时新闻任务、浏览器一键备份恢复或 AI 草稿审核平台。旧库可能保留历史表，但不代表当前支持对应产品能力。

资料切片和向量存在不等于已交付完整 RAG 问答，当前向量是本地哈希表示，不是下载的语义模型。

验收步骤及本次实际验证结果分别见 [测试与验收说明](测试/测试与验收说明.md) 和 [V1定版验证记录](测试/V1定版验证记录.md)。版本标识统一不等于消除全部已知问题或完成公网生产验收。
