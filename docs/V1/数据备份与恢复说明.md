# AI 工作台 V1 数据备份与恢复说明

## 1. 当前能力与数据边界

V1 没有浏览器一键备份、还原、JSON 导出或删除撤销接口。备份使用 PostgreSQL 工具和人工文件备份，不将未来设想接口写成已有功能。

应保护的内容：

- 整个业务数据库：模块、标签、资料、面试题及追问、GitHub 项目与备注、索引任务、片段、identity 序列；旧库历史表也纳入备份。
- 实际 `WORKBENCH_DATA_DIR/imports/`：通过上传保留的原 Markdown 副本。
- 运行配置：`.env`、IDE/终端配置中的密钥另行加密保管，不打入普通分享包，不提交 Git。

AI 热点和上游元数据的进程内缓存不需备份。粘贴及手工正文以数据库为准，没有同名磁盘文件属于正常情况。

## 2. 备份步骤

1. 停止脚本或 IDE 管理的业务服务，避免备份数据库期间上传副本继续变化。
2. 确认目标数据库无误，并确保剩余磁盘空间足够。
3. 用 `pg_dump` 的 custom 格式生成备份。下列命令中的数据库名称按实际替换，使用已配置的 `.pgpass` 或交互式凭证，不把密码写在命令或文档中。
4. 单独备份实际 imports 目录，记录备份时间、数据库名、工程版本 1.0.0 和文件目录。
5. 将备份移到安全存储；数据库正文和个人备注同样可能包含敏感信息。

```bash
bash scripts/stop-local.sh
mkdir -p data/backups
pg_dump --dbname=workbench --format=custom --file=data/backups/工作台数据库备份.dump
pg_restore --list data/backups/工作台数据库备份.dump
```

示例文件名固定，已有同名文件时请使用新的时间戳名称，避免覆盖唯一备份。数据库不是默认本机 workbench 时显式指定 host/port/user；不要用示例地址误备份其他库。

`pg_restore --list` 只检查备份目录可读，不代表数据已完整验证；可靠性需要在独立数据库进行恢复演练。

## 3. 恢复原则

恢复前先备份当前库，创建独立空数据库进行演练，并保证目标具备 pgvector 扩展能力。原库不能直接作为“试试看”的还原目标。

由操作者确认目标后，使用 `pg_restore` 恢复到新库，核对资料、题目、追问、分类、GitHub 备注、外键及序列；恢复文件副本到匹配目录。之后才将 Java/Python 连接同时切换到验证过的新库并重启。

本说明不提供自动覆盖原库或自动删除旧表的命令。回退应用版本涉及相应数据库结构，不能只回退前端而假设 UUID 与自增主键等结构兼容。

## 4. 删除与归档

资料归档保留正文，可恢复处理；删除资料清理数据库关联及索引，但上传副本不会自动删除。删除题目会失去其追问，删除 GitHub 本地记录会失去个人备注，不影响远程仓库。

清理磁盘副本前核对其是否被当前资料使用。不要将全量清库脚本作为日常测试或磁盘清理工具。

迁移前备份是执行 [数据库脚本](SQL/数据库脚本使用说明.md) 的前置条件，SQL 的事务保护不能替代备份。
