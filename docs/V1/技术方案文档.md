# AI 工作台 V1 技术方案文档

版本：V1 / 1.0.0。基准日期：2026-11-19。描述当前代码，不以历史规划替代已实现能力。

## 1. 总体架构

```text
浏览器（React + TypeScript + Vite）
  └── Java REST API（Spring Boot）
        ├── PostgreSQL：分类、资料、面试题、GitHub、任务
        ├── 本地 imports/：上传 Markdown 副本
        ├── Python API：内部解析/索引接口、健康检查
        ├── 模型聊天 API：用户点击生成面经时调用
        ├── AIHOT API：按需读取热点
        └── GitHub REST API：预览、新增、手动同步

Python worker
  └── 轮询 PostgreSQL 索引任务
        └── Markdown 规范化 → 切片 → 离线哈希向量 → pgvector
```

前端默认 5173，Java 默认 8080，Python API 默认 8000。Java 统一处理业务写入和外部请求，Python 负责文档处理；worker 是独立进程，不是仅启动 Python API 就自动运行。

### 技术栈

| 层次 | 当前选型 |
| --- | --- |
| 前端 | React 19、TypeScript、Vite 7、Lucide 图标、marked 与本地 Markdown 渲染控制 |
| Java | Java 21、Spring Boot 3.4.5、Spring MVC、JDBC、Bean Validation、springdoc |
| Python | Python 3.14、FastAPI、Pydantic Settings、psycopg、独立 worker |
| 存储 | PostgreSQL 16、pgvector、磁盘上传副本 |
| 测试 | JUnit/MockMvc/模拟 HTTP、Node test runner、pytest、隔离 PostgreSQL |

没有引入 Redis、消息中间件、自动迁移框架或认证平台。版本标识统一为 1.0.0，不调整第三方依赖版本。

## 3. 数据结构

### 当前业务表

| 表 | 主键及主要内容 |
| --- | --- |
| `core.modules` | UUID；名称、描述、图标、排序、ACTIVE/ARCHIVED 状态 |
| `core.tags` | UUID；名称、可选父标签、颜色 |
| `core.documents` | UUID；模块、标题、正文、规范化正文、来源、哈希、状态、索引错误及时间 |
| `core.interview_questions` | BIGINT identity；问题、答案、详细解释、追问文本、模块、难度、掌握状态、创建来源 |
| `core.document_tags` | 资料 UUID + 标签 UUID 复合主键 |
| `core.interview_question_tags` | 题目 BIGINT + 标签 UUID 复合主键 |
| `core.index_jobs` | UUID；任务类型、资源、重试次数、状态、错误及执行时间 |
| `rag.document_chunks` | 资料片段、标题路径、顺序、内容、元数据、1024 维向量等 |
| `core.github_projects` | BIGINT identity；分类、仓库身份及概况、备注、同步状态、ETag、同步时间 |

当前代码不新增新闻表或 AI 草稿表。旧库可能保留 `core.ai_question_drafts`、`core.interview_question_sources` 等历史表，不能直接删表；主键迁移按已知引用转换。

### 关键约束与标识

- 面试题和 GitHub 项目的本地主键使用 BIGINT，JSON 序列化为十进制字符串，前端不转 Number 做 ID 排序。其他对象仍使用 UUID，不是全库改自增。
- 面试题 `difficulty` 为 EASY/MEDIUM/HARD，`mastery_status` 为 NOT_STARTED/LEARNING/MASTERED，`source_type` 为 MANUAL/DOCUMENT。
- 题目来源仅记录类别，不建立资料到题目的新来源外键；更新题目不修改来源。
- 模块/标签删除通过外键置空或级联清理关联行，内容保留。
- GitHub 分类 PERSONAL_DEMO/LEARNING；同步 PENDING/SUCCESS/FAILED。
- GitHub 同分类中 `lower(full_name)` 唯一，非空 GitHub 远程 ID 也按分类唯一；可跨分类保存同仓库。
- 追问写入现有 TEXT 字段，不新建子题表：

```json
{"version":1,"items":[{"question":"追问 Markdown","answer":"回答 Markdown"}]}
```

`version: 1` 是追问内容格式版本，不是独立产品版本，不随本次定版改成 1.0.0。兼容读取旧合并 Markdown，修改追问后写回结构化内容，删除最后一条保存空字符串。

## 4. 资料处理流程

1. Java 校验引用，保存正文及 SHA-256。Markdown 导入查询相同正文的未归档资料并复用；上传时保留磁盘副本。
2. 非归档资料创建 INDEX_DOCUMENT 任务，同一资料已有活跃任务时复用。
3. worker 从 PENDING/RETRY_WAITING 中领取任务，使用 `FOR UPDATE SKIP LOCKED` 避免同时领取。
4. Python 规范化标题、段落、列表和代码块，按标题路径生成片段。
5. 计算本地哈希向量并写入 `rag.document_chunks`，更新规范化正文、索引时间和任务状态。
6. 异常记录失败信息及重试状态；归档资料不会被任务状态误恢复为可用。

资料状态为 PENDING_INDEX、INDEXING、INDEXED、FAILED、ARCHIVED。任务状态包括 PENDING、RUNNING、RETRY_WAITING、SUCCEEDED、FAILED，具体重试以任务字段及 worker 实现为准。

当前 embedding 是确定性的离线哈希算法；虽然配置名包含 BAAI/bge-m3，代码并未下载或执行该语义模型。已有向量不能证明语义检索质量，V1 也未暴露完整 RAG 问答入口。

资料编辑、索引任务和标签关系由 Java Repository 配合事务维护。上传副本属于数据库事务外的磁盘文件，不保证数据库失败时自动回收。

## 5. 模型生成与标签推荐

### 资料生成面经

`POST /api/v1/documents/{id}/generate-interview-questions` 读取资料标题和正文，通过兼容聊天接口的 `/chat/completions` 调用模型。默认配置键 DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_CHAT_MODEL。

正文截取前 14,000 字符，温度 0.2、max_tokens 3000、要求 JSON 输出；连接超时 5 秒、读取超时 45 秒。只接受合法难度、非空问题和答案，最多返回 3 条。模型返回异常转为明确业务错误。

生成结果仅返回本次请求。前端确认后逐条 POST 面试题，携带资料模块/标签、NOT_STARTED 和 DOCUMENT 来源。没有服务端批量原子保存和重复采纳幂等键，失败时可能部分成功。

### 标签推荐

`POST /api/v1/tags/recommend` 接收内容，在已有标签名称中做大小写不敏感匹配；出现次数优先、使用次数次之、最多 3 条。不访问模型，不创建标签。

当前 `TagService.recommend` 使用 `PageRequest.of(0, 1000)`，而公共分页校验最大为 100，非空内容可能在读取标签前直接被拒绝。此处是已有缺口，本次定版整理仅记录，不悄然修改业务逻辑；页面推荐成功仍需修复后另行验收，手动选择/创建标签不因此消失。

## 6. AI 热点请求

固定上游 AIHOT：`/api/v1/items?mode=selected&window=7d&by=published&limit=100`。最多取 3 页，用发布时间转换到 Asia/Shanghai，筛出今天和昨天，去重安全原文链接和标题。

今天按时间倒序最多 5 条；昨天按 score/scores 的总评分倒序、时间倒序补充，缺少评分显式警告。概述直接使用上游文本，不额外调用模型。

串行锁合并并发刷新；缓存 TTL 10 分钟，成功后的最短刷新间隔 1 分钟，临时网络错误及 502/503/504 重试耗尽后冷却 15 秒。条件请求使用 ETag，重试时保留条件头和当前分页游标。

每页首次失败后最多重试 2 次，仅重试网络访问错误及 502/503/504；证书错误、其他 HTTP 错误、解析及数据结构错误不立即重试。两次退避分别为 500 毫秒和 1 秒，另加 0～150 毫秒随机抖动。429、带有 Retry-After 的 503 不立即重试，按响应头中的秒数或 HTTP 日期退避，最少等待 1 分钟；其余不重试错误保留 1 分钟冷却。

连接超时 3 秒、读取超时 5 秒。整个查询共用 15 秒预算，包含并发等待、所有分页、响应正文读取及重试等待；虚拟线程承载上游查询，预算耗尽即取消，工作线程不更新共享缓存。前端加载最长 20 秒，不叠加自动重试。

上游失败时同日旧快照可降级，跨日不将旧新闻冒充今天。缓存随进程退出丢失，无持久化或定时任务。失败、限流、无新闻分别处理。日志记录失败页码、尝试次数、异常及根因类型、HTTP 状态、累计耗时、下次重试等待时间和冷却时间；成功重试记录恢复日志。跨线程保留请求 ID，不记录上游响应正文、完整异常消息或凭证。

## 7. GitHub 获取与同步

地址仅接受 HTTPS GitHub 仓库根路径，拒绝其他域名、凭证、端口、参数、片段及仓库内部路径。用户地址只用来提取 owner/repo，实际请求固定 `api.github.com`。

仅读取公开仓库。服务端可选 GITHUB_TOKEN，固定官方 API 请求才携带，不入库或返回前端。限制跳转到官方仓库 API，防止把用户 URL 当任意 HTTP 代理。

元数据缓存 5 分钟、最多 200 个键；主动同步 10 秒重复点击保护；持久化 ETag，304 保留概况并推进成功同步时间。限流读取 Retry-After/X-RateLimit-Reset 设置进程级退避，不用重启来规避上游限额。

新增获取失败保存地址/备注为 PENDING；同步失败标 FAILED，保留旧概况及上次成功时间。更新只改分类/备注，同步不覆盖个人字段；同类冲突返回 409，不自动合并项目。

## 8. API 总览

Java 路径前缀保持 `/api/v1`，产品定版不更改路由。分页 `page` 从 0 开始，`size` 默认 20、允许 1～100。

| 方法与资源 | 说明 |
| --- | --- |
| GET/POST `/modules`；GET/PATCH/DELETE `/modules/{id}` | 模块 CRUD |
| GET/POST `/tags`；GET/PATCH/DELETE `/tags/{id}` | 标签 CRUD |
| POST `/tags/recommend` | 本地内容标签推荐 |
| GET/POST `/interview-questions`；GET/PATCH/DELETE `/interview-questions/{id}` | 题目分页、详情和维护 |
| GET/POST `/documents`；GET/PATCH/DELETE `/documents/{id}` | 资料维护 |
| POST `/documents/import` | JSON 粘贴或 multipart Markdown 上传 |
| GET `/documents/{id}/jobs`；POST `/documents/{id}/reindex` | 任务历史、重建索引 |
| POST `/documents/{id}/generate-interview-questions` | 生成不落库结果 |
| GET `/ai-news`，可传 `refresh=true` | 热点聚合，响应 no-store |
| GET `/github-projects`，category 必填 | 分类分页、关键词查询 |
| GET `/github-projects/counts`；POST `/github-projects/preview` | 分类计数、预览 |

Python 内部接口：GET `/internal/v1/health`、POST `/internal/v1/parse/markdown`、POST `/internal/v1/index/documents`。Python 健康接口不证明 worker 正在处理任务。

## 9. 前端状态与安全边界

sessionStorage 只存视图、详情 ID、GitHub 分类；刷新重新请求数据，失效 ID 回列表。旧 UUID 题目详情选择会失效，模块位置仍可保留。不是完整 URL 路由或跨设备同步。

API 错误包含 code、message、requestId 和可选 details，Java 请求日志通过 request_id 关联；不在响应输出数据库密码和模型密钥。Markdown 过滤原始 HTML 和不安全链接。GitHub/新闻链接保留来源，外链新窗口使用防护属性。

本地单用户版本没有认证授权边界，不应直接暴露公网。启动服务、CORS 或“本地”名称并不构成网络访问控制；部署需限制监听地址及防火墙。

## 10. 迁移、运行与已知限制

数据库初始化不自动执行 `docs/SQL`。`CREATE TABLE IF NOT EXISTS` 不会把旧 UUID 题目表转换为自增，也不保证补齐所有历史字段；必须按脚本说明检查已有库。旧字段精简脚本会删除 source_type，须在来源迁移前执行，当前结构不要重跑。

现有重要限制：

- 题目、资料、模块和标签页面主要加载前 100 条，筛选范围受此限制；GitHub 已有服务端翻页。
- 标签推荐存在分页上限冲突，需单独修复和验收。
- 模型生成依赖外部服务、内容截断、人工核验和逐条保存；来源不是强血缘追踪。
- 新闻和 GitHub 依赖上游规则、网络和 JVM 代理；API 可用不代表每个外部数据源可用。
- 备份恢复为人工操作，没有浏览器端备份、撤销删除或恢复任务。
