# AI 工作台 V2 路线图与验收方案

## 1. 交付策略

V2 采用“先基础设施、再学习闭环、最后 AI 增强”的顺序。每个阶段都要有可独立使用的结果，不把所有能力压到最后一次发布。

## 2. 阶段计划

### 阶段 0：基线与迁移准备

**目标**：让 V2 的数据和任务演进可控。

**工作项**：

- 引入 Flyway 或同等级迁移机制，建立 V1 基线。
- 抽取 Java API client、分页模型和前端错误处理。
- 将前端资料、题目、模块、标签改为服务端分页。
- 扩展任务表：重试退避、幂等键、进度和取消状态。
- 补齐模块/标签更新接口与前端能力。
- 建立迁移数据库、空数据库和升级数据库三套自动化验证。

**出口标准**：

- V1 现有页面行为不回归。
- 100 条以上资料和题目可以分页访问。
- 重复点击重试不会创建重复活跃任务。
- V1 数据库升级后资料、题目、分类和历史索引任务都保留。

### 阶段 1：批量导入与数据保护

**目标**：让用户可以稳定地把一批本地资料纳入工作台。

**工作项**：

- 批量 Markdown/文本/HTML/PDF 导入。
- 导入预览、去重、冲突处理和每文件错误。
- 导入批次任务、单文件重试和进度展示。
- JSON/Markdown 导出。
- 完整备份包、校验和和过期清理。
- 恢复前确认、保护性快照和恢复后校验。

**出口标准**：

- 10、100、500 个文件批量导入均能完成，失败文件不影响其他文件。
- 重复导入结果稳定且可解释。
- 导出包可在空数据库恢复，恢复后题目、资料、标签、模块和来源文件可核对。
- 备份包不包含密码、API Key 和绝对本机路径。

### 阶段 2：今日复习与学习反馈

**目标**：建立每日可执行的复习闭环。

**工作项**：

- 复习卡片、复习记录和 FSRS 兼容调度。
- 今日队列、逾期队列和按模块/标签筛选。
- 答题后反馈和下次复习时间展示。
- 首页行动指标和学习活动。
- 从资料片段创建手工候选题。

**出口标准**：

- 新题可以进入今日队列。
- 完成一次复习后有不可变记录，题目下次到期时间正确变化。
- 关闭并重启服务后队列和历史不丢失。
- 旧题目没有复习记录时仍能正常显示和编辑。

### 阶段 3：统一搜索与来源关联

**目标**：让用户能够按关键词和概念找到可定位的依据。

**工作项**：

- 全局搜索 API 和页面。
- PostgreSQL 全文检索和片段级结果。
- 真实 Embedding Provider 接口和 hash-v1 回退。
- pgvector 语义召回、RRF 混排和索引版本。
- 资料片段与面试题来源关联。
- 详情页引用定位和失效来源提示。

**出口标准**：

- 无模型时关键词搜索仍可用。
- 有模型时同义表达可以召回相关片段。
- 搜索结果能定位到资料和章节，结果不包含已归档内容，除非用户明确选择。
- 删除资料不会删除题目，但来源关系会标记为失效。

### 阶段 4：有来源的 AI 辅助

**目标**：降低出题、检查和提炼成本，同时保留用户控制权。

**工作项**：

- 可插拔 Chat Provider。
- 基于检索片段的资料问答。
- 候选题生成、答案检查和关键点提炼。
- AI 运行记录、提示版本、来源片段和接受/拒绝操作。
- AI 任务超时、重试和失败恢复。

**出口标准**：

- 没有模型配置时基础产品正常运行。
- 每个回答或候选题都展示来源和生成元数据。
- AI 不能直接覆盖正式资料和正式答案。
- 接受结果后可以追溯到 AI 运行和原始资料片段。

## 3. 优先级排序

| 优先级 | 能力 | 原因 |
|---|---|---|
| P0 | 服务端分页、任务框架、批量导入、导出备份 | 解决规模、可靠性和数据安全基础问题 |
| P0 | 今日复习、复习记录、调度 | 直接形成用户每天可执行的核心价值 |
| P0 | 统一关键词搜索 | 即使没有模型也能立即提升可用性 |
| P1 | 真实语义向量和混合检索 | 提升相关性，但依赖索引版本和模型选择 |
| P1 | 来源关联 | 是 AI 可控和答案可信的前提 |
| P1 | AI 候选题、答案检查和资料问答 | 在基础闭环稳定后增加效率 |
| P2 | DOCX、网页收藏、浏览器扩展 | 扩展输入来源，暂不影响核心闭环 |
| P2 | 云同步、多用户协作 | 需要另立产品和安全设计 |

## 4. 测试与验收

### 4.1 自动化测试

- Java：分页、筛选、批量操作、来源关系、复习状态机、任务幂等和异常映射。
- Python：每种 Parser Provider、分块定位、Embedding Provider 回退、任务重试。
- 前端：搜索条件、复习流程、导入批次状态、错误和空状态。
- 集成：新库初始化、V1 升级、备份恢复、worker 并发领取。

### 4.2 手工验收主路径

1. 导入一批包含 Markdown、文本、HTML、PDF 的文件。
2. 观察重复、失败、重试和索引完成状态。
3. 用标题关键词、正文关键词和概念词分别搜索。
4. 从搜索结果打开资料片段并创建候选面试题。
5. 将题目加入今日复习，完成至少两次不同反馈。
6. 检查到期时间、历史记录和首页行动指标。
7. 导出资料和题库，创建完整备份。
8. 在空数据库恢复，核对资料、题目、来源、复习卡片和原始文件。
9. 配置 AI Provider 后运行一次问答和一次候选题生成。
10. 拒绝一条候选结果、接受并修改另一条候选结果，检查审计和来源记录。

### 4.3 性能基线

V2 首次发布建议以本机单用户规模为基线：

- 1,000 份资料、10,000 个片段、5,000 道题目可以正常分页和筛选。
- 首页和普通列表不因总数据量线性加载全部内容。
- 单个导入任务失败不会阻塞同批次其他文件。
- 搜索结果首屏以分页方式返回，长正文不在列表接口重复传输。

这些是工程验收基线，不是对未来硬件环境的承诺；实际数据增长后再调整索引和并发参数。

## 5. 发布拆分建议

### V2.0

包含阶段 0、阶段 1、阶段 2，以及阶段 3 的关键词搜索和来源关系基础。

### V2.1

包含真实 Embedding、混合检索和阶段 4 的 AI 候选能力。

### V2.2 或独立版本

评估 DOCX/网页采集、桌面化、云同步和多人协作。若 V2.0 的复习完成率和内容复用率没有明显提升，不应优先扩张到这些方向。
