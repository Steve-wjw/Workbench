# AI 工作台 V2 产品分析与发展方向

> 基于当前工作区中的 V1 PRD、用户文档、备份设计、React 前端、Java API、Python 索引服务和 PostgreSQL 初始化脚本整理。

## 1. 当前产品判断

### 1.1 产品定位

当前产品是一个本地优先的个人 AI 学习与面试准备工作台，核心资产包括：

- 资料：Markdown、手工正文、原始上传副本、规范化文本和索引片段。
- 面试题：问题、简短答案、详细解释、关键点、难度和掌握状态。
- 组织体系：模块与标签。
- 后台处理：资料解析、分块、索引、失败记录和重试。

当前实现不是一个 AI 聊天产品，也不是一个多人协作知识库。V1 有意移除了 AI 草稿审核、AI 查询和模型配置页面，保留了稳定的本地资料维护能力。

### 1.2 V1 已经解决的问题

| 能力 | 当前实现 |
|---|---|
| 资料入库 | 手工资料、Markdown 粘贴、Markdown 文件上传 |
| 资料维护 | 阅读、编辑、归档、删除、重新索引 |
| 题库维护 | 面试题 CRUD、关键点、难度和掌握状态 |
| 组织 | 模块一对多、标签多对多 |
| 处理可靠性 | `PENDING/RUNNING/SUCCEEDED/FAILED/RETRY_WAITING` 任务状态、最多三次尝试、活跃任务复用 |
| 本地运行 | React + Java API + Python API/Worker + PostgreSQL，服务不依赖外部大模型 |
| 数据安全边界 | 数据库和本地上传目录纳入备份范围，敏感配置不进入导出包 |

V1 的价值已经从“页面原型”进入“可持续积累内容的本地工具”阶段，这是 V2 可以继续做深的基础。

### 1.3 当前主要限制

以下判断来自当前代码，而不是抽象的产品假设。

| 领域 | 现状 | 直接后果 |
|---|---|---|
| 列表规模 | 前端启动时以 `size=100` 一次加载题目、资料、模块和标签；题目与资料筛选主要在浏览器完成 | 数据量增长后首屏变慢，超过 100 条的内容无法正常进入页面 |
| 资料格式 | 导入入口只支持 Markdown；Python 解析器只实现 Markdown 解析 | 外部资料进入工作台前仍需人工转换 |
| 搜索 | Java 资料查询使用 `ILIKE`；虽然数据库有 `tsvector` 和向量列，但当前页面没有检索 API，向量也没有用于相似度查询 | 只能做字面匹配，不能按概念、同义表达或相关章节查找 |
| 向量质量 | `embedding.py` 使用确定性哈希向量；配置中的 `BAAI/bge-m3` 只是旧标识，并没有加载 BGE 模型 | 当前向量不能被当作真实语义检索质量 |
| 复习闭环 | 题目只有 `NOT_STARTED/LEARNING/MASTERED` 三种状态，没有到期时间、复习记录、答题反馈或间隔算法 | 用户需要自己决定每天复习什么，系统无法形成行为闭环 |
| 来源关系 | 题目有 `source_type` 字段，但当前没有资料到题目的来源关联表；删除资料时也不会保留正式题目的来源关联 | 无法回答“这道题来自哪份资料、哪些资料支持这个答案” |
| 导出恢复 | 备份与导出只有设计约定，当前没有浏览器端导出、备份任务或恢复流程 | 数据可通过人工 `pg_dump` 保护，但日常使用成本高 |
| 后台任务 | 只有资料索引任务，数据库约束把 `index_jobs` 固定为 `INDEX_DOCUMENT` | 导入、导出、AI 生成等新任务无法沿用同一可靠性模型 |
| 前端管理 | 后端已经有部分模块/标签更新能力，但前端模块页面只提供创建和删除；标签父子关系字段也没有在 UI 暴露 | 管理能力与 API 能力不一致，后续分类体系难以维护 |
| 可用性反馈 | 首页只有资料数、题目数和最近内容，没有待复习数、失败任务数之外的行动指标 | 用户知道“存了多少”，但不知道“今天应该做什么” |

### 1.4 核心机会

V2 最值得解决的不是“增加更多页面”，而是把已有的内容资产转化成连续行为：

```text
导入资料
  -> 解析与索引
  -> 统一检索
  -> 生成或维护面试题
  -> 进入复习队列
  -> 用户反馈掌握程度
  -> 调整后续复习计划
  -> 用来源和搜索结果持续回到原文
```

这条链路一旦成立，产品才从“知识仓库”变成“学习执行系统”。

## 2. V2 战略方向

### 2.1 方向一：内容处理从单条维护升级为可控的批量入库

**目标**：降低资料从本地文件到可检索内容的摩擦，并让重复、失败、格式不兼容都可解释。

**方案**：

- 支持文件和目录批量导入，第一批增加纯文本、HTML 和 PDF；DOCX 作为后续适配器。
- 导入先进入预览和校验阶段，再提交为异步任务。
- 按文件内容哈希去重，保留“跳过、更新、另存为新资料”三种冲突策略。
- 解析器采用适配器接口，每种格式输出统一的 `normalized_text`、章节路径、页码或来源元数据。
- 在前端增加导入批次页，显示每个文件的状态、错误、重试和跳过原因。
- 保留原始文件副本，正文、解析结果和来源信息写入数据库。

**价值**：先把已有资料完整纳入资产库，才能让后续搜索和 AI 辅助有足够数据基础。

### 2.2 方向二：从关键词查找升级为可解释的混合检索

**目标**：用户既能精确找到原文，也能按概念找到相关章节，并能看到答案依据。

**方案**：

- 新增统一搜索入口，搜索资料、面试题和标签关系。
- 默认使用关键词检索 + 语义检索的混合排序；任一能力不可用时自动降级。
- 结果按资料、题目、章节片段分组，并支持模块、标签、来源类型、状态过滤。
- 片段结果展示标题路径、资料标题和命中原因；进入详情时定位到原文片段。
- 语义模型作为 Provider 插件接入，默认仍可使用本地关键词检索，不强制联网。
- 所有 AI 答案必须带来源片段 ID，来源不可追溯时不生成“确定性结论”。

**价值**：搜索从“有没有这个词”变成“这个知识在哪里、与什么相关、依据是什么”。

### 2.3 方向三：从掌握状态升级为真正的复习系统

**目标**：让用户每天打开产品就知道要复习什么，并且每次复习都能改变后续计划。

**方案**：

- 为每道面试题创建复习卡片，记录下次复习时间、稳定性、难度和复习次数。
- 采用 FSRS 兼容的间隔调度方案，不在业务代码中自创间隔算法。
- 提供“今日复习”队列：按到期时间、难度、模块和预计时长排序。
- 每题先展示问题，用户主动查看答案后反馈“忘记、困难、一般、简单、很简单”。
- 将一次复习写入不可变的复习记录，再更新复习卡片；掌握状态作为汇总展示，不再作为唯一事实来源。
- 支持从资料阅读页将片段转为候选面试题，候选题必须由用户确认后进入正式题库。
- 首页从内容统计改为“待复习数、逾期数、索引失败数、最近学习活动”的行动面板。

**价值**：这是 V2 最重要的留存和复用能力，也是最不依赖外部模型的产品价值。

### 2.4 方向四：AI 作为有来源的助理，而不是不可控的内容生产器

**目标**：在不恢复 V1 已取消的强制草稿审核流程的前提下，减少整理和出题的手工成本。

**推荐的 AI 能力**：

1. 基于资料片段回答问题，并展示引用来源。
2. 根据指定资料或章节生成候选面试题。
3. 对已有答案做“缺失点检查”和“表达优化建议”。
4. 将用户选中的资料片段提炼为关键点、术语或复习卡片候选。

**边界**：

- AI 输出一律标记为候选或建议，不直接覆盖正式资料和正式答案。
- 用户可以逐项接受、修改或丢弃；接受后记录生成来源、模型、提示版本和依据片段。
- 没有模型配置时，以上入口可以隐藏或只提供人工流程，不能影响 V1 核心能力。
- 不在 V2 做开放式 Agent、自动改写整个资料库、自动删除或自动合并正式内容。

### 2.5 方向五：数据保护从人工命令升级为产品能力

**目标**：用户可以低风险地导出、备份和恢复自己的知识资产。

**方案**：

- 内容导出：JSON、Markdown 和可读的复习题库格式。
- 完整备份：数据库 dump + 上传原文件，生成带版本和校验信息的备份包。
- 导出和备份都采用异步任务，完成后提供文件名、大小、校验和、过期时间。
- 恢复默认先校验备份包，再要求明确的本地确认；恢复前自动生成当前数据的保护性快照。
- 导出内容移除密码、API Key、绝对路径和内部日志。

## 3. V2 的产品取舍

### 3.1 V2 应该做什么

- 把资料规模和检索体验做成可持续使用的基础设施。
- 把面试题从静态记录变成有计划、有反馈的复习卡片。
- 以来源和可接受性约束 AI 输出。
- 让导入、导出、备份、恢复具备可见的任务状态。
- 保持单用户、本地优先和不依赖外部服务即可运行。

### 3.2 V2 暂不做什么

- 多用户、权限、团队协作和公开分享。
- 云端同步和跨设备冲突解决。
- 自动化 Agent 编排、后台自动修改正式内容。
- 视频/PPT 生成等与当前学习闭环距离较远的媒体能力。
- 以“向量库替换”为目标的独立基础设施迁移；当前 PostgreSQL + pgvector 足以支撑 V2。

## 4. 成功标准

V2 不用“接入了几个模型”衡量，而用以下结果衡量：

| 指标 | V2 目标方向 |
|---|---|
| 内容可处理性 | 常见资料可批量导入，失败项可单独重试，重复导入结果可解释 |
| 搜索有效性 | 关键词和概念搜索都能返回可定位的资料片段，结果包含来源 |
| 复习执行率 | 用户打开首页能直接进入今日队列，并能完成一次完整复习 |
| 资产可迁移性 | 可导出正式内容，可创建可校验备份，并能在空数据库恢复 |
| AI 可控性 | AI 结果不覆盖正式内容，所有接受结果均可追溯到来源 |
| 工程可靠性 | 任务可重试、可观测、幂等；V1 数据升级不丢失 |
